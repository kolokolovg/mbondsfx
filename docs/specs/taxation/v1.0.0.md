# Спецификация налогооблагаемой базы и НДФЛ по облигациям — v1.0.0

Согласование: **APPROVED** (владелец, 2026-10-22). Реализация: **NOT_STARTED**.
Статус целевой: `target ≠ implemented`. Текущее поведение (`CouponReceiptService`, `TaxCorrectionService`)
принимает только фактические `gross`, `tax`, `net` и налог не рассчитывает; эта спецификация его не
описывает и не отменяет до утверждения (раздел 11). Основания и границы сверки с законодательством — раздел 10.

## 1. Область и обозначения

Спецификация задает чистые расчеты: налогооблагаемая база события (купон, амортизация, погашение, продажа),
НДФЛ с учетом прогрессивной шкалы, отложенное обязательство и событие удержания. Все суммы — `Money`
(`BigDecimal`), валюта — рубль; ставки — `BigDecimal`. Даты, статус резидентства, признаки счета, накопленная
годовая база и внешние оценки передаются явно; часы и «текущий год» по умолчанию не используются.

| Обозначение | Смысл |
|---|---|
| `GrossCouponAmount` | начисленный денежный купон (фактическая сумма к выплате до налога) |
| `TotalAcquisitionCost` | «чистая» цена приобретения тела облигации (clean price × количество): без комиссий и без НКД (R6.1) |
| `TotalNominalBeforeEvent` | суммарный номинал позиции непосредственно перед событием |
| `AmortizationNominalPaid` | выплаченная доля номинала при амортизации |
| `FinalNominalPaid` | сумма окончательного погашения номинала |
| `CapitalExpenses` | комиссии и иные расходы на приобретение, явно переданные вызывающим |
| `AcquiredAccruedInterest` | НКД, уплаченный при покупке |
| `CostBeforeEvent` / `CostAfterEvent` | остаточная стоимость тела облигации до/после события (R2.1) |
| `RemainingCost` | не списанная через амортизацию часть `TotalAcquisitionCost` перед погашением |
| `TAX_LIABILITY` | накопленное обязательство по налогу, зафиксированному и не списанному (раздел 7) |

## 2. Купон (R1)

- R1.1 База: `TaxableBase_Coupon = GrossCouponAmount` — 100% начисленного купона по всем типам облигаций,
  включая ОФЗ и муниципальные. Вычетов и льгот нет, кроме уменьшения на НКД, уплаченный при покупке (R1.5).
- R1.2 `GrossCouponAmount ≥ 0`; иначе `IllegalArgumentException`.
- R1.3 Тип счета один — `BROKERAGE`. Событие удержания зависит от явного параметра `taxWithheldUpstream`
  (по умолчанию `false`), который передает вызывающий:
  - R1.3a `false`: налог рассчитывается по R4 и фиксируется как обязательство (R7.1); списание откладывается
    до вывода средств или годового расчета (R7.3, R7.4). До списания `NetCoupon` равен `GrossCoupon`.
  - R1.3b `true`: налог удержан внешним налоговым агентом. Вызывающий передает фактические `gross`, `tax`,
    `net`; должно выполняться `gross = tax + net`, иначе `IllegalArgumentException`. Фактический `tax`
    проводится как сейчас (`D TAX_WITHHELD / C CASH`). Расчетный налог по R4 — только справочная сверка и
    не подменяет фактический; расхождение исправляется через `TaxCorrectionService`.
  - R1.3c База такого купона (`TaxableBase = gross`) включается в `YTD`.
  - R1.3d Модель обязательства (раздел 7) и блокировка ИИС-3 (R1.4) к событию с `true` не применяются.
  - R1.3e `taxWithheldUpstream` относится к купону. Депозитарий не признается налоговым агентом при выплате
    сумм в погашение номинала (амортизация, погашение): налог по ним уплачивается по ст. 228 НК РФ (п. 6
    ст. 226.1); такой случай вне области. При выплате купона депозитарием на брокерский счет налоговым агентом
    признается брокер (п. 2 ст. 226.1), т.е. `false`.
- R1.4 Для счета ИИС-3 (R6.3) налог рассчитывается и копится как обязательство; налоговое списание
  (R7.3, R7.4) не выполняется до закрытия счета (R7.7).
- R1.5 НКД, уплаченный при покупке, при условии что он определяется до выплаты купона (явный признак лота
  `AccruedInterestDeductibleFromCoupon`), уменьшает доход по первому купону, полученному после приобретения
  (п. 13 ст. 214.1 НК РФ). Для лота `i` с долей купона `Gross_i = GrossCouponAmount × Quantity_i / Σ Quantity`:
  ```
  Applied_i            = min(Gross_i, AcquiredAccruedInterest_i)
  TaxableBase_Coupon   = Σ (Gross_i − Applied_i)
  AcquiredAccruedInterest_i после = AcquiredAccruedInterest_i − Applied_i
  ```
  Остаток `AcquiredAccruedInterest_i` учитывается в расходах при погашении или продаже (R3.3) — так, что НКД
  уменьшает базу ровно один раз. Применение — только к первому купону после покупки лота; последующие купоны
  не уменьшаются. Лот без признака (НКД не определялся до выплаты) учитывается только по R3.3.

## 3. Амортизация (R2)

Сама выплата номинала налогом не облагается; материальная выгода возникает, если бумага куплена с дисконтом.
Расходы на покупку списываются пропорционально доле амортизации.

```
AmortizationShare            = AmortizationNominalPaid / TotalNominalBeforeEvent   (справочно)
AllocatedCost                = CostBeforeEvent × AmortizationNominalPaid / TotalNominalBeforeEvent
TaxableBase_Amortization     = max(0, AmortizationNominalPaid − AllocatedCost)
CostAfterEvent               = CostBeforeEvent − AllocatedCost
```

- R2.1 Для первого события `CostBeforeEvent = TotalAcquisitionCost`; для последующих `CostBeforeEvent` — это
  `CostAfterEvent` предыдущего шага (формула `TotalAcquisitionCost × share` завышает списание).
  `AmortizationShare` каждый раз считается от `TotalNominalBeforeEvent` данного события.
- R2.2 Если `CostBeforeEvent ≥ TotalNominalBeforeEvent`, то `TaxableBase_Amortization = 0` строго (для первого события это
  `TotalAcquisitionCost ≥ TotalNominalBeforeEvent`; для последующих сравнивается остаточная стоимость, а не исходная,
  иначе теряется дисконт: cost 950, номинал 1000, выплата 500 → остаток 475/500, следующая выплата дает базу).
- R2.3 `0 < AmortizationNominalPaid ≤ TotalNominalBeforeEvent`, `TotalNominalBeforeEvent > 0`; иначе IAE.
- R2.4 `AmortizationShare`, `AllocatedCost`, `TaxableBase` не округляются (R6.2); накопленная сумма
  `ΣAllocatedCost_i` не превышает `TotalAcquisitionCost` (следует из R2.1 и `share ≤ 1`).
- R2.5 Порядок вычисления `AllocatedCost` (R6.2): сначала умножение `CostBeforeEvent × AmortizationNominalPaid`,
  затем ОДНО деление на `TotalNominalBeforeEvent` (DECIMAL128). Вычисление через предварительно округленную
  `AmortizationShare` НЕ ДОЛЖНО использоваться: `810 × (1/9)` дает `89,99…9` и после `RoundingMode.DOWN` может
  потерять копейку налога.

## 4. Погашение (R3)

```
RemainingCost         = TotalAcquisitionCost − Σ AllocatedCost_i
TaxableBase_Maturity  = max(0, FinalNominalPaid − RemainingCost − CapitalExpenses − AcquiredAccruedInterest)
```

- R3.1 Все слагаемые неотрицательны и в одной валюте. `RemainingCost = CostAfterEvent` последней
  амортизации (или `TotalAcquisitionCost`, если амортизаций не было).
- R3.2 Если выражение под `max` отрицательно, база `0`; убыток не переносится этой подсистемой — он
  передается в общий модуль сальдирования торговых операций (вне области).
- R3.3 `CapitalExpenses` и `AcquiredAccruedInterest` — обособленные статьи расходов: они уменьшают базу
  ровно ОДИН раз, при окончательном погашении (`TaxableBase_Maturity`) или продаже (раздел 8); часть НКД,
  уже учтенная по первому купону (R1.5), в этих расходах не учитывается повторно. Они НЕ входят
  в `TotalAcquisitionCost`, `CostBeforeEvent` и `AllocatedCost` (в амортизации не участвуют).

## 5. Ставка и резидентство (R4)

- R4.1 Резидент, прогрессивная шкала по совокупной годовой базе (YTD) за календарный год, ставка
  применяется к части базы в соответствующей ступени:

  | Ступень (совокупная годовая база, руб.) | Ставка |
  |---|---|
  | до 2 400 000 включительно | 13% |
  | свыше 2 400 000 до 5 000 000 | 15% |
  | свыше 5 000 000 до 20 000 000 | 18% |
  | свыше 20 000 000 до 50 000 000 | 20% |
  | свыше 50 000 000 | 22% |
- R4.2 Нерезидент: фиксированная ставка **30%**.
- R4.3 Налог события вычисляется приращением: `Tax(event) = TaxTotal(YTD + base) − TaxTotal(YTD)`, где
  `YTD` — накопленная налогооблагаемая база того же налогового года, переданная явно, а `TaxTotal` —
  кусочно-линейная функция шкалы (R4.1). Для нерезидента `Tax = 0.30 × base`.
- R4.4 Налоговый год — календарный год даты события; дата передается явно.

## 6. Округление и инварианты (R5, R6)

- R5.1 Инвариант знака: `TaxableBase ≥ 0` для любого события (купон, амортизация, погашение, продажа).
- R5.2 `Tax ≥ 0` и `Tax ≤ TaxableBase`.
- R6.1 `TotalAcquisitionCost` — строго «чистая» цена тела (clean price × количество); комиссии и НКД
  передаются отдельными параметрами (R3.3).
- R6.2 Округление (проектный инвариант): все промежуточные величины (`AmortizationShare`, `AllocatedCost`,
  `CostAfterEvent`, `TaxableBase`, `TaxTotal`) ведутся в `BigDecimal` с `MathContext.DECIMAL128` без промежуточных
  округлений. Итоговый налог события `Tax(event)` округляется до целых копеек (scale 2) строго
  `RoundingMode.DOWN`. Накопленная база `YTD` — неокругленная.
- R6.3 Флаг счета ИИС-3 — явный параметр; для такого счета налоговое списание заблокировано до закрытия
  (R1.4, R7.7). ИИС-3 — признак брокерского счета, а не отдельный тип.

## 7. Отложенный налог (R7)

Целевая модель для ledger; double-entry спецификация новой версии выводится из этого раздела.

- R7.1 Фиксация (`taxWithheldUpstream = false`, R1.3a): налог события, рассчитанный по R4, фиксируется как
  обязательство клиента без движения `CASH`: `D TAX_DEFERRED_OFFSET / C TAX_LIABILITY`. `TAX_DEFERRED_OFFSET` —
  контрсчет собственного капитала клиента с дебетовым сальдо. Счета расхода не вводятся: НДФЛ физлица не
  является расходом, вычитаемым из торгового дохода.
- R7.2 Read view: `AvailableCash = CASH − TAX_LIABILITY` по портфелю и валюте; рядом остаются `cashBalances()` и
  `taxWithheldBalances()`. Средства под `TAX_LIABILITY` нельзя тратить на покупки и иные операции, кроме вывода
  (R7.3): при выводе налог удерживается из самой выводимой суммы.
- R7.3 Вывод (триггер `WITHDRAWAL`): налог удерживается из выводимой суммы, но не больше обязательства и
  не больше суммы вывода; другие активы для этого не продаются (п. 11 ст. 226.1 НК РФ: если налог нарастающим
  итогом превышает сумму выплаты, налог исчисляется с суммы выплаты; п. 10: удержание — из рублевых средств
  на счете на дату удержания). Сальдирование убытков года вне области (R3.2): налог при выводе берется от
  `TAX_LIABILITY`, накопленного по событиям без учета убытков; возможное превышение против налога нарастающим
  итогом по закону исправляется годовым расчетом (R7.4), где `YearTax` передается с учетом сальдирования.
  ```
  TaxToWithhold = min(TAX_LIABILITY, RequestedWithdrawal)
  NetPayout     = RequestedWithdrawal − TaxToWithhold
  TAX_LIABILITY после = TAX_LIABILITY − TaxToWithhold
  ```
  - `0 < RequestedWithdrawal ≤ CASH` (по портфелю и валюте), иначе IAE. Лимит — `CASH`, а не `AvailableCash`:
    налоговая часть выводимой суммы идет на погашение обязательства. Оценка портфеля не нужна.
  - Все величины — `Money` без округления (разность и `min` точны); сумма вывода и обязательство уже в копейках.
  - Примеры (`TAX_LIABILITY = 13 000`): вывод 50 000 → налог 13 000, `NetPayout` 37 000, обязательство 0;
    вывод 30 000 (весь `CASH`) → налог 13 000, `NetPayout` 17 000; вывод 10 000 → налог 10 000,
    `NetPayout` 0, остаток обязательства 3 000 переносится на следующие выводы или учитывается в годовом расчете (R7.4).
  - Проводки: погашение обязательства `D TAX_LIABILITY / C TAX_DEFERRED_OFFSET` и фактическое удержание
    `D TAX_WITHHELD / C CASH` на `TaxToWithhold`; выплата `NetPayout` — отдельный вывод из `CASH`.
- R7.4 Годовой расчет (триггер `YEAR_END`): выполняется явной операцией с датой в январе года, следующего
  за налоговым (п. 14 ст. 226.1 НК РФ: удержание возможно до истечения одного месяца с даты окончания
  налогового периода; сообщение о невозможности удержания направляется в налоговый орган до 25 февраля —
  вне области); часы по умолчанию не используются. Вызывающий явно
  передает `TaxYear`, `YearTax` — итоговый налог года с учетом сальдирования внутри года (сальдирование,
  включая отдельную базу дивидендов, и перенос убытков прошлых лет вне области, R3.2) и `AlreadyWithheld` —
  удержано за этот год по выводам (R7.3). Суммы, удержанные внешним агентом (R1.3b), в `AlreadyWithheld` не
  входят: они не проходят через обязательство брокера.
  ```
  Due = YearTax − AlreadyWithheld
  ```
  - `Due > 0`: к удержанию `Due` из свободного рублевого `CASH`: `ToWithhold = min(Due, CASH)`; ценные бумаги
    для этого не продаются. Недостаток `Due − ToWithhold` остается неудержанным: фиксируется как отдельный
    факт «неудержанный налог» (передача сведений в ФНС — вне области), в новом году не переносится в `TAX_LIABILITY`.
  - `Due < 0`: переплата `−Due` возвращается на `CASH` отдельной append-only операцией (возврат излишне
    удержанного налога, обычно в январе).
  - `Due = 0`: ничего не удерживается.
  - После расчета `TAX_LIABILITY` за `TaxYear` равен 0: остаток обязательства закрывается против
    `TAX_DEFERRED_OFFSET` (с учетом `Due`, `ToWithhold` и возврата).
  - Операции годового расчета и возврата — отдельные виды, не `TAX_CORRECTION` по `TAX_WITHHELD`; расширение
    `OperationKind` определяется новой версией double-entry.
- R7.5 `TAX_LIABILITY ≥ 0` после любой операции; `TaxToWithhold ≤ TAX_LIABILITY`.
- R7.6 Новые счета меняют `LedgerChart`: старые снапшоты несовместимы по value-equality. Изменение
  `BondAccountingPolicy` — MAJOR.
- R7.7 ИИС-3. Вывод средств с ИИС-3 без закрытия счета невозможен: операция `WITHDRAWAL` для такого счета
  отклоняется слоем `application` (`InvestmentAccount`), ledger ее не получает. Триггер `YEAR_END` для ИИС-3
  не запускает налоговое списание; `TAX_LIABILITY` продолжает копиться.
  - Закрытие счета: `application` по явно переданным датам (`ClosingDate`, `TermEndDate` — окончание срока,
    после которого действует льгота; вычисляется вызывающим вне подсистемы по правилам закона о сроке ИИС-3)
    определяет `EarlyClosure = ClosingDate < TermEndDate`. Закрытие в момент
    окончания срока или после него — не досрочное.
  - **Досрочное закрытие (`EarlyClosure = true`):** удерживается накопленное обязательство целиком:
    `ToWithhold = min(TAX_LIABILITY, CASH)`, как в R7.3 (проводки погашения обязательства и удержания);
    бумаги для этого не продаются. Недостаток остается неудержанным: фиксируется как факт «неудержанный
    налог» (R7.4), обязательство при этом закрывается.
  - **Закрытие в срок или после (`EarlyClosure = false`):** вызывающий явно передает `TaxOnExcess` — налог на
    часть финансового результата сверх лимита вычета (по умолчанию `0`). Лимит (30 млн руб. по всем договорам
    ИИС-3, прекращенным в одном налоговом периоде) общий для нескольких счетов, поэтому его применение и расчет
    `TaxOnExcess` выполняет вызывающий вне подсистемы. Требуется `0 ≤ TaxOnExcess ≤ TAX_LIABILITY`, иначе IAE.
    Удерживается `ToWithhold = min(TaxOnExcess, CASH)` как при досрочном закрытии (проводки R7.3); бумаги не
    продаются; недостаток фиксируется как «неудержанный налог» (R7.4). Остаток обязательства закрывается
    против `TAX_DEFERRED_OFFSET` (`D TAX_LIABILITY / C TAX_DEFERRED_OFFSET`) без движения `CASH`.
    При `TaxOnExcess = 0` налог не удерживается, `CASH` не меняется.
  - Ledger не знает про ИИС, срок и досрочность: он получает явный вход — удержание суммы `ToWithhold`
    (R7.3) либо закрытие обязательства без удержания; проверка состояния инвестсчета, определение
    `EarlyClosure` и выбор операции — в `application` (`InvestmentAccount`). Отдельных статусов расчета в
    ledger нет.

## 8. Продажа и учет лотов FIFO (R8)

Налог при продаже считается по себестоимости, списанной методом FIFO по лотам позиции. Средневзвешенная
учетная стоимость налоговой себестоимостью не является. Ledger ведет позицию очередью лотов FIFO; это
требование к double-entry v-next (вместе с разделом 7).

- R8.1 Лот — часть позиции одной покупки: `Quantity`, дата и порядковый номер покупки (порядок FIFO:
  сначала по дате, при равенстве — по порядковому номеру операции в ledger; задается явно), `RemainingCost`
  (чистая стоимость тела, R6.1, после амортизаций R2), `CapitalExpenses`, `AcquiredAccruedInterest`
  (R3.3, учитываются один раз при выбытии лота).
- R8.2 Продажа `Quantity = q`, рыночная цена продажи за единицу `SalePrice` (чистая, без НКД; передается явно):
  `Proceeds = SalePrice × q`. Также явно передается `AccruedInterestReceived ≥ 0` — НКД, полученный при продаже
  (не вычисляется). `SalePrice` и `AccruedInterestReceived` — в рублях: перевод цены из процентов номинала
  (от текущего номинала с учетом амортизации) выполняется вне расчета. Списание: лоты берутся от самого
  раннего; последний лот может списываться частично, в доле `f = consumed / lotQuantity` берутся
  `RemainingCost`, `CapitalExpenses`, `AcquiredAccruedInterest`. Нехватка бумаг (`q > Σ lotQuantity`) — IAE.
- R8.3 Для каждого затронутого лота `i` с долей выручки `Proceeds_i = SalePrice × consumed_i`:
  ```
  Result_i = Proceeds_i + AccruedInterestReceived × consumed_i / q
             − f_i × RemainingCost_i − f_i × CapitalExpenses_i − f_i × AcquiredAccruedInterest_i
  Result   = Σ Result_i − SaleExpenses   // SaleExpenses — R8.5
  TaxableBase_Sale = max(0, Result)
  RealizedLoss     = max(0, −Result)
  ```
  НКД, полученный при продаже, входит в доход той же сделки и зачитывается убытком по телу в ее пределах.
  Умножение до единственного деления (R2.5), DECIMAL128 без промежуточных округлений (R6.2). Налог события —
  R4.3 с округлением `DOWN`. `RealizedLoss` не переносится этой подсистемой: передается наружу для сальдирования
  (R3.2); излишне зафиксированный налог исправляется годовым расчетом (R7.4).
- R8.4 Амортизация (R2) и погашение (R3) выполняются по лотам: `CostBeforeEvent` — `RemainingCost` лота,
  номинал выплаты распределяется пропорционально номиналу лота. Результаты лотов складываются линейно, без
  `max` на уровне лота, и только затем применяется ограничение снизу:
  `TaxableBase_Amortization = max(0, Σ (Paid_i − AllocatedCost_i))`; для погашения аналогично
  `TaxableBase_Maturity = max(0, Σ (FinalNominalPaid_i − RemainingCost_i − CapitalExpenses_i − AcquiredAccruedInterest_i))`.
  Премиальный лот тем самым гасит дисконтный. Для позиции из одного лота результат совпадает с R2–R3.
- R8.5 Комиссия и прочие расходы продажи (`SaleExpenses`, явно, ≥ 0) уменьшают `Result` однократно; налог и
  тариф по-прежнему не рассчитываются автоматически, комиссия берется как заданная вызывающим.
- R8.6 `YTD` для налога продажи — накопленная база того же года (R4); база продажи входит в `YTD`.
- R8.7 Требования к ledger: позиция содержит упорядоченные лоты FIFO; продажа списывает лоты по R8.2 и порождает
  проводки стоимости по списанной себестоимости; восстановление из снапшота сохраняет лоты и их порядок.
  Лоты — часть нового `LedgerState` (R7.6). Налоговый расчет остается в `core.bond.calculation`, ledger хранит
  лоты и не знает ставок.

## 9. Примеры (трассируемость тестов)

### 9.1. Сквозной сценарий

Номинал 1000 руб., покупка с дисконтом за 900 руб. (`TotalAcquisitionCost = 900`, комиссии и НКД 0),
резидент, `YTD` в начале года = 0. Ставка 13% на всех шагах (накопленная база ≤ 2 400 000). Налог события
`Tax = TaxableBase × 13%`, округление `DOWN` до копеек (R6.2).

| Шаг | Событие | Вход | `share` | `AllocatedCost` | База | НДФЛ | `CostAfterEvent` | `YTD` после |
|---|---|---|---|---|---|---|---|---|
| 1 | Купон (А) | `Gross = 50` | — | — | 50 | 6.50 | 900 | 50 |
| 2 | Амортизация 10% номинала (Б) | `Paid = 100`, `NominalBefore = 1000` | 100/1000 = 0.1 | 900 × 0.1 = 90 | max(0, 100 − 90) = 10 | 1.30 | 900 − 90 = **810** | 60 |
| 3 | Вторая амортизация (Б2), снова 100 руб. (10% исходного номинала) | `Paid = 100`, `NominalBefore = 900` | 100/900 = 1/9 | 810 × 1/9 = 90 | max(0, 100 − 90) = 10 | 1.30 | 810 − 90 = **720** | 70 |

Пояснения:
- Шаг 3 иллюстрирует R2.1: расчет от `CostBeforeEvent = 810`, а не от `TotalAcquisitionCost = 900`
  (буквальная формула дала бы `900 × 1/9 = 100`, база 0, остаток `900 − 90 − 100 = 710` — расхождение с R2.1).
- `AllocatedCost` на шаге 3 вычисляется по R2.5: `810 × 100 / 900 = 90` точно (умножение, затем одно деление);
  налог `10 × 13% = 1.30` точный.
- Погашение после шага 3 (Д'): остаток номинала 800, `FinalNominalPaid = 800`, `RemainingCost = 720`,
  расходы 0, НКД 0: база = `max(0, 800 − 720) = 80`, НДФЛ = 10.40.

### 9.3. Продажа (R8)

**Один лот.** Резидент, `YTD = 0`. Покупка 1 бумаги: `RemainingCost = 900`, `CapitalExpenses = 2`,
`AcquiredAccruedInterest = 10`. Продажа: `SalePrice = 1000`, `AccruedInterestReceived = 30`, `SaleExpenses = 2`.
`Result = 1000 + 30 − 900 − 2 − 10 − 2 = 116`; база 116; НДФЛ `116 × 13% = 15.08`.

**Два лота, частичная продажа (FIFO).** Лот A: 100 шт., `RemainingCost = 9000`, `CapitalExpenses = 10`,
`AcquiredAccruedInterest = 100`. Лот B (позже): 100 шт., `RemainingCost = 9500`, расходы 0, НКД 0.
Продажа 150 шт.: `SalePrice = 98`, `AccruedInterestReceived = 300`, `SaleExpenses = 15`.

| Лот | `consumed`, `f` | Выручка | НКД получ. | Списано | `Result_i` |
|---|---|---|---|---|---|
| A | 100, f = 1 | 9800 | 300 × 100/150 = 200 | 9000 + 10 + 100 = 9110 | 890 |
| B | 50, f = 0.5 | 4900 | 300 × 50/150 = 100 | 4750 + 0 + 0 = 4750 | 250 |

`Result = 890 + 250 − 15 = 1125`; база 1125; НДФЛ `1125 × 13% = 146.25`. Остаток: лот B, 50 шт.,
`RemainingCost = 4750`.

## 10. Основания и границы сверки с законодательством

Сверка выполнена 2026-10-22 по первичным текстам (consultant.ru, nalog.gov.ru).

- ст. 214.1 НК РФ, п. 7, 10, 13, 14: доходы от реализации и купоны входят в доходы по операциям с ценными
  бумагами; расходы по ФИФО; НКД покупки уменьшает первый купон (R1.5); расходы при частичном погашении
  признаются пропорционально доле дохода от погашения (R2); база — положительный финансовый результат по
  совокупности операций. НКД, полученный при продаже, включается в доход (разъяснение Минфина, письмо от
  09.10.2017 № 03-04-06/65742, по вторичным источникам) — R8.3.
- ст. 226.1 НК РФ, п. 2, 6, 10, 11, 12, 14: налоговые агенты, порядок удержания, вывод средств, срок и
  недостаток средств — R1.3e, R7.3, R7.4. Утверждение о неудержании налога депозитарием по ОФЗ нормой не
  подтверждается и в спецификацию не вносится.
- ИИС-3 (nalog.gov.ru): вычет финансового результата — не более 30 млн руб. по всем договорам, прекращенным в
  одном налоговом периоде; предоставляется налоговым органом по декларации либо налоговым агентом по заявлению.
  Минимальный срок договора в источниках указан по-разному (10 лет на странице ФНС; 5 лет для 2024–2026 по
  справочным источникам), первичный текст нормы об ИИС-3 в ст. 219.1 на consultant.ru не найден. Поэтому срок,
  лимит и размер налога сверх лимита вычисляются вызывающим и передаются явно (`TermEndDate`, `TaxOnExcess`, R7.7).
- Принятые допущения владельца: вычет НКД покупки по первому купону ограничен размером доли купона лота,
  `min(Gross_i, AcquiredAccruedInterest_i)` (R1.5); сальдирование убытков и перенос убытков прошлых лет вне
  области (R3.2, R7.4, R8.3).

Открытых вопросов нет.
