# Спецификация базисов 30/360, 30E/360, 30E+/360 и нулевой доли года — v1.0.0

Согласование: **APPROVED**. Реализация: **IMPLEMENTED**.
Источник определений: «Методика расчета НКД и доходности» Московской биржи, раздел 1.1, формула (1)
(файл `yield2-by-sections-2.pdf`; в репозитории методика пересказана в
`docs/methodology/bond-yield-methodology.md`).

## 1. Область

`core.money.DayCounts` уже содержит `ACT/365F`, `ACT/360`, `ACT/ACT.ISDA`, `30E/360`.
Эта версия добавляет `30/360` и `30E+/360` и фиксирует для `BondCalculations` правило нулевой доли года.
Финансовая семантика существующих конвенций не меняется, кроме правила из раздела 4.

## 2. Определение числа дней

Для дат `T1 = (Y1, M1, D1)` и `T2 = (Y2, M2, D2)`:

```
N = D2 − D1 + 30 × (M2 − M1) + 360 × (Y2 − Y1)                                (1)
```

Варианты отличаются только правкой `D1`, `D2` (и `M2`) до применения (1):

| Код | Правило |
|---|---|
| `30/360` | Если `D1 = 31`, то `D1 := 30`. Если `D2 = 31` и `D1 ∈ {30, 31}` (после п. 1 `D1 = 30`), то `D2 := 30`. |
| `30E/360` | Если `D1 = 31`, то `D1 := 30`. Если `D2 = 31`, то `D2 := 30`. (Эквивалентно текущей реализации `min(D, 30)`.) |
| `30E+/360` | Если `D1 = 31`, то `D1 := 30`. Если `D2 = 31`, то `D2 := 1` и `M2 := M2 + 1` (с переносом года при `M2 = 13`). |

Год-доля: `yearFraction = N / 360` (`MathContext.DECIMAL128`). Знак: для `T2 < T1` результат противоположен
по знаку результату для `(T2, T1)` — аналогично существующей реализации `30E/360`.
Особых правил конца февраля нет: источник их не содержит, и они не вводятся.

Правило «`D1` приходится на 30 или 31» для `30/360` означает значение `D1` исходной даты `≥ 30`.

## 3. Примеры (для тестов)

| T1 | T2 | 30/360 | 30E/360 | 30E+/360 |
|---|---|---|---|---|
| 2026-01-30 | 2026-01-31 | 0 | 0 | 1 |
| 2026-01-31 | 2026-03-31 | 60 | 60 | 61 |
| 2026-01-15 | 2026-03-31 | 76 | 75 | 76 |
| 2026-01-29 | 2026-03-31 | 62 | 61 | 62 |
| 2026-12-31 | 2027-01-31 | 30 | 30 | 31 |

Строки 3–4 показывают отличие `30/360` от `30E/360`: при `D1 < 30` значение `D2 = 31` не заменяется.

## 4. Нулевая доля года в расчете купона и НКД

Контракт `BondCalculations` (раздел `segmentYearFraction`):

1. Для положительного календарного интервала сегмента купона/НКД доля года должна быть строго положительной.
   Иначе — `IllegalArgumentException("DayCount must return a positive fraction for a positive interval")`.
2. **Исключение:** для `DayCounts.thirtyE360()` и `DayCounts.thirty360()` (сравнение по identity) нулевая доля
   допустима и дает нулевой вклад в НКД/купон (пример: период с 30-го числа, дата расчета 31-е).
3. Исключение **не** распространяется на `ACT/365F`, `ACT/360`, `ACT/ACT.ISDA`, `30E+/360` и любые другие
   реализации `DayCount`, включая «двойников» 30E/360 с иным объектом.
4. Полный период `KnownCoupon` (доля всего периода) остается строгим: нулевая доля — ошибка.
5. Отрицательная доля отвергается всегда.
