# Спецификация базисов подсчета дней — v1.0.1 (дополнение к v1.0.0)

Согласование: **APPROVED** (содержание выбрано пользователем 2026-10-22 как вариант «v1.0.1 + код»).
Реализация: **IMPLEMENTED**. Версия v1.0.0 не перезаписывается и остается в силе во всем, что
не изменено ниже.

## Причина

По формуле (1) методики MOEX `30E+/360` дает 1 день для интервала 31-е → 31-е (`D2 := 1`, `M2 := M2 + 1`).
Для расчета НКД это приводит к ненулевому начислению (1/360 доли) на саму дату начала купонного периода,
если он начинается 31-го. Это противоречит смыслу полуоткрытого интервала `[начало периода, settle)`.

## Изменения

1. **Нулевой интервал.** Для `BondCalculations.accrued` при `settle == accrualStart` прошедшая доля года
   всегда равна нулю и вычисляется без обращения к `DayCount` (для любой конвенции).
2. Это правило относится к прошедшей части `KnownCoupon` и к формульным купонам одинаково;
   значение `DayCount.yearFraction(T, T)` в расчетах НКД не используется.
3. Прошедшая часть `KnownCoupon` при `settle > accrualStart` проверяется по тем же правилам строгости, что и
   сегменты (v1.0.0, раздел 4): нулевая доля допустима только для `DayCounts.thirtyE360()` и
   `DayCounts.thirty360()` по identity; для прочих `DayCount` (включая «двойников») — `IllegalArgumentException`
   с прежним сообщением. Полный период `KnownCoupon` остается строгим.
4. Сами определения `DayCount` (раздел 2 v1.0.0, включая `30E+/360` для 31→31 = 1 день) **не меняются**.

## Тестовая трассируемость (target)

| Требование | Свидетельство |
|---|---|
| п. 1–2 | НКД при settle = начало периода, начинающегося 31-го, равен 0 для `30E+/360`, `30/360`, `30E/360`, ACT |
| п. 3 | двойник 30/360 на прошедшей части `KnownCoupon` при settle > start дает IAE; identity-инстансы дают 0 |
