# Заключение: покрытие кода формальной верификацией (2026-10-22)

Основано на `docs/plans/verification.md`, `LedgerProperties` и составе `core/src/main`.
Сборка не запускалась, числа PIT/JaCoCo взяты из документации и не перепроверялись.

**Формальной верификации в проекте нет.** Нет доказательств теорем, SMT/JML/OpenJML, model checking
и TLA+. `verification.md` прямо указывает, что проверки не являются формальным доказательством
соответствия спецификации. Ниже — автоматизированные проверки, наиболее близкие к формальным.

## Что есть

| Средство | Охват | Сила |
|---|---|---|
| jqwik, `LedgerProperties` | Только `core.ledger`: пять свойств по 250 попыток (четыре базовых и агрегатное со смешанными цепочками RUB/USD/JPY). Проверяют баланс проводок по валютам, пропорциональное снятие с HALF_UP, `TAX_WITHHELD` вне spendable, append-only для `TAX_CORRECTION`, неизменяемость и round-trip restore. | Случайные тесты, не доказательство. Конкурентный CAS не покрыт. |
| ArchUnit (`BytecodeArchitectureContractTests`) | Структура `:core`: направления зависимостей между пакетами, отсутствие HTTP/XML и application/integrations. | Только структура, не поведение. |
| Root `ModulePathContractTests` | JPMS-границы произведенного distribution. | Инкапсуляция, не логика. |
| PIT | `core.ledger`, `core.money`, `core.bond.calculation`: убито 497 из 511 мутантов (97%), порог 93%. | Качество тестов, не корректность. 12 выживших и 2 непокрытых мутанта задокументированы как эквивалентные или относящиеся к мертвому коду. |
| JaCoCo с порогами LINE/BRANCH | Все подпроекты, кроме root. | Охват строк и ветвей. |

Из убитых мутантов только 3 приписаны jqwik-свойствам; остальные убили example-based тесты.
Свойства дают малую часть реальной защиты.

## Пробелы

1. **`core.bond`** (16 файлов): `BondDefinition`, `FloatingRateFormula`, `IndexationRule`, купонные
   расписания и инварианты дат. Property-тестов нет, PIT на пакет не нацелен. Крупнейший непокрытый пакет домена.
2. **`core.bond.calculation`** (`BondCalculations`, `AccruedInterest`): есть PIT, но нет свойств.
   Не проверены монотонность НКД, неотрицательность, суммирование купонов, вырожденные периоды.
3. **`core.money`**: нет свойств для day-count, `HolidayCalendar.shift`, арифметики и округления `Money`
   (коммутативность и ассоциативность сложения, сохранение валюты, идемпотентность округления).
4. **`core.id`**: проверок нет.
5. **`:application`, `:persistence-memory`, `:integrations*`**: нет jqwik, ArchUnit и PIT.
   Не проверены `CouponReceiptService`, `TaxCorrectionService`, CAS-коммит, репозитории и их
   конкурентность, fixing-мост `IndexValueSourceAdapter`, разбор XML/JSON MOEX и CBR.
6. **Ledger**: нет доказательства достижимости состояний (`restore` не доказывает историческую
   достижимость, первый CAS не подтверждает подлинность chart). Не покрыты конкурентный CAS и
   произвольные цепочки с налоговыми поправками; свойства не охватывают все `OperationKind`,
   цепочки короткие.
7. **Трассируемость «требование → свидетельство»** есть только для double-entry v1.0.0
   (`docs/specs/double-entry/README.md`), но не для всего кода.

## Оценка

Только `core.ledger` покрыт чем-то, близким к проверке инвариантов, и то на уровне случайных тестов.
Остальной домен (`bond`, `calculation`, `money`) защищен example-тестами и мутационным скором;
application и интеграции — только example-тестами и порогами JaCoCo.

## Рекомендации по приоритету

1. jqwik-свойства для `core.money` и `core.bond.calculation`: алгебра `Money`, инварианты НКД,
   floor/cap плавающей ставки, индексация.
2. Свойства для инвариантов `BondDefinition` и расписания (даты, упорядоченность, отсутствие
   пересечений); включить `core.bond` в PIT.
3. Расширить `LedgerProperties`: все `OperationKind`, длинные цепочки с налоговыми поправками,
   проверка воспроизводимости состояния через replay.
4. Для application и `persistence-memory`: тесты конкурентного CAS (jcstress или многопоточный
   стресс-тест), property-тесты идемпотентности и атомарности репозиториев.
5. Для настоящей формальной верификации — OpenJML/KeY или модель TLA+ для `Ledger.apply`,
   CAS и restore. Отдельное решение: по AGENTS.md нужны явное одобрение и проверка лицензий.
6. Расширить таблицу «требование → тест → вид свидетельства» с v1.0.0 на весь домен.

## Нужна ли новая версия спецификации для пунктов 1–3

Нет. Пункты добавляют только тесты; production-код и финансовая семантика не меняются, а v1.0.0
уже IMPLEMENTED. Обновлять нужно документацию: `docs/plans/verification.md` (таблица свойств, пакеты PIT)
и, желательно, реестр тестов в `docs/specs/double-entry/README.md` (трассируемость, не требования).
Если свойство найдет реальное расхождение с поведением, исправление потребует отдельного
согласования, возможно с новой версией спецификации. После включения `core.bond` в PIT
перепроверьте `mutationThreshold` и пороги JaCoCo.
